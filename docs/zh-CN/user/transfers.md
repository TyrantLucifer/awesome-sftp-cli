# 传输和 Job

[English](../../user/transfers.md)

AMSFTP 会把复制、移动、重命名和删除都作为可持久恢复的后台 Job 执行。文件栏负责
收集你的选择和确认，daemon 负责记录并执行工作。关闭 TUI 不会取消这些 Job。

## 复制文件

1. 使用 `Space`、`v` 或 `V` 选择一个或多个条目。没有选择时会使用光标所在
   条目。
2. 按 `y`。这一步只记录文件引用，不会开始读取数据。
3. 按 `Tab` 切换到目标栏。
4. 按 `p`。
5. 检查来源、目标、条目数和可能的冲突选择，然后确认。
6. 按 `J` 查看新建的 Job。

AMSFTP 先把每个目标写入私有临时内容。通过所选完成检查并提交后，最终名称才会出现。失败的传输
不会被报告成完整的最终文件。

目录复制采用增量遍历。符号链接会作为符号链接显示；递归复制目录时不会沿它进入
目标。

## 移动文件

流程与复制相同，只需把 `y` 换成 `d`：

1. 选择来源。
2. 按 `d`。
3. 切换到目标栏并按 `p`。
4. 检查移动确认，再启动 Job。

小写 `d` 只会把选择标记成剪切，本身不会删除任何内容。

同一个端点支持安全重命名时，AMSFTP 可以直接使用它。否则，移动会先复制、验证并
提交目标，再重新检查和删除原文件。如果原文件已经变化，或者无法证明删除成功，
Job 会保留已经验证的目标，并以“来源已保留”结束。继续操作前，请检查两份文件。

## 重命名单个条目

把光标放在一个文件或目录上，按 `r`，输入一个普通的新条目名称并确认。重命名不
接受多选。

它仍然会作为 Job 出现，因此执行结果和冲突都可见。

## 删除文件

大写 `D` 是唯一的删除入口，与小写 `d` 完全分开。

1. 选择要删除的文件。
2. 按 `D`，检查已经冻结的选择。
3. 确认范围。
4. 如果端点不支持可靠的回收站，再检查不可逆警告并确认一次。

当前本地和标准 SFTP 通道都没有声明可靠回收站，因此删除通常需要两次确认。
AMSFTP 会拒绝根目录、空目标、已经变化的目标和其他不安全对象。递归删除不会沿符号
链接进入它指向的位置。

## 解决目标冲突

可以选择：

- **覆盖**：确认记录的目标状态没有变化后才替换它。
- **跳过**：保持当前来源和目标不变。
- **自动重命名**：生成一个不冲突的目标名称。
- **询问**：暂停 Job，等待你选择覆盖、跳过或自动重命名。

在 Job 抽屉中：

| 按键 | 作用 |
| --- | --- |
| `w` / `x` / `a` | 覆盖 / 跳过 / 自动重命名当前冲突 |
| `W` / `X` / `A` | 把同一选择应用到此 Job 中匹配的冲突 |

“全部应用”只限于当前 Job，不会变成全局默认值。

## 查看和控制 Job

按 `J` 打开 Job 抽屉，使用 `j`、`k` 选择任务。

| 按键 | 可用时的作用 |
| --- | --- |
| `P` | 暂停排队中或正在运行的任务 |
| `U` | 恢复暂停任务，或重试可恢复的等待 |
| `C` | 取消尚未结束的任务 |

标题只会显示当前状态真正允许的动作。已完成、失败和取消的 Job 仍然可以选择，但
不会显示不存在的操作。

命令行提供相同的控制能力：

```sh
amsftp job list
amsftp job events job_aaaaaaaaaaaaaaaaaaaaaaaaaa --after 0 --limit 50
amsftp job pause job_aaaaaaaaaaaaaaaaaaaaaaaaaa
amsftp job resume job_aaaaaaaaaaaaaaaaaaaaaaaaaa
amsftp job cancel job_aaaaaaaaaaaaaaaaaaaaaaaaaa \
  --confirm job_aaaaaaaaaaaaaaaaaaaaaaaaaa
```

取消时必须再次提供完全相同的 Job ID，防止粘贴或输入错误导致其他任务被取消。
脚本需要稳定结构化输出时，可以添加 `--format json`。

## 理解常见状态

- **排队 / 运行 / 验证**：任务正在等待、传输或检查结果。
- **等待认证**：通过 OpenSSH 更新或完成认证，然后恢复任务。
- **等待冲突处理**：选择覆盖、跳过或自动重命名。
- **已暂停**：持久进度会被保留；准备好后按 `U`。
- **等待重试**：可以安全重试的传输错误正在等待下一次尝试。
- **已完成但来源保留**：目标已经验证，但移动操作无法证明可以安全删除来源，因此
  有意保留。
- **失败 / 已取消**：开始新任务前，请检查 Job 并刷新两端。

传输速度使用短时间移动平均值，只在数据流动时显示。目录 Job 的已传输字节数会在
当前文件完成验证前持续更新；已完成条目数只会在该文件提交后增加。目录操作在部分
阶段可能还无法确定总字节数。

普通复制默认采用**协议确认**：所有写入都必须收到确认，字节数必须匹配，源和目标
文件句柄必须成功关闭，发布操作也必须成功。它采用接近原生普通 SFTP 的完成标准，
同时保留 Job 专属临时文件和防止意外覆盖的保护。成功路径不回读目标，也不强制 fsync。

内容校验与文件同步是独立设置：

- `transfer.verification: "sha256"` 会读取并计算临时目标和发布后目标的摘要。
  一次上传因此写入一份文件数据，再回读两份同等大小的数据。
- `transfer.durability: "completion"` 在关闭、发布前同步一次文件；上传文件数据的
  同步语义可与原生 `sftp put -f` 对照。
- `transfer.durability: "checkpoint"` 同步每个检查点；默认值 `"none"` 不承诺强制同步。

fsync 成功是文件数据同步的依据，不证明父目录命名空间已持久化，也不证明底层硬件
诚实执行了请求。SSH 保护传输中的数据，写入确认不等于独立验证存储内容。严格校验
需要额外 I/O，也不能替代 fsync。移动和编辑回写保留 SHA-256 检查及同步检查点。
显式设置 `require_strong` 也会强制 SHA-256。已有 Job 保留冻结时的完成策略。

每个 SFTP 文件最多保持 64 个 32 KiB 请求在途。新普通复制最多传输 64 MiB，或在五秒后的下一个
数据包边界，检查点会记录已确认字节、源摘要状态及观察到的临时文件身份。这是候选
恢复点；只有实际同步成功才推进 `durable_bytes`。它不需要 64 MiB 内存缓冲。
限速使用独立的数据包预算，不会缩短检查点间隔。

`amsftp job list --format json` 分别提供实时 `bytes`、已记录的
`acknowledged_bytes` 和 `durable_bytes`；`verification`、`durability` 是冻结策略。
`content_verified` 表示已完成目标的内容证明；`verified_bytes` 统计累计回读工作，
包含恢复读取，因此可能超过文件大小。Jobs 抽屉会区分正在完成提交与正在计算摘要。
各阶段耗时可能重叠，不能相加当作总耗时。

新目录复制在最多 8 个文件之间共享 128 个在途数据请求的预算。小文件按大小申请
窗口；大文件上传最多使用两个完整窗口，双 SSH 端点的大文件中继同时使用一个文件
的读、写窗口。旧冻结策略继续使用原有的一到两个槽。内存、连接及带宽上限仍然生效，
父目录先于子项创建，最多保存 8 个未完成文件的检查点。重启后会重新检查已完成文件。

发布响应丢失时，包括协议确认模式在内，都必须取得内容证明才能报告成功，不能只凭
大小和修改时间消除这种不确定性。

## 中断后的恢复

daemon 会在写入过程中记录安全进度。重启后，它会重新检查来源、部分目标和最终
目标，再决定是否继续。状态不确定时，Job 会明确暂停或失败，不会靠猜测处理。

传输可能留下超出最后一个候选恢复点的数据。恢复时，即使大小和修改时间仍然匹配，
也会按源摘要验证候选前缀，再将额外尾部与未变化的源文件比较，证明一致后才把该
部分文件截回候选偏移。如果部分文件短于已保存的候选点、已经变化或无法证明一致，
会保留文件并报告冲突，不会静默追加或丢弃字节。服务器或机器崩溃后，未同步的数据
可能丢失。

临时文件创建后，AMSFTP 先记录空文件的恢复身份，再响应取消；要求同步检查点的
策略还会同步该文件，避免取消留下无法识别的新部分文件。

暂停通常会保留可以继续使用的部分数据。如果删除会损失恢复证据，取消或失败也可能
保留 Job 自己的部分文件，或编辑过程的安全副本。排查 Job 时不要手动删除
`.part`、备份、SQLite 或 WAL 文件。

如果移动操作在目标提交后、来源删除前中断，来源会留在原处。检查两边后再恢复。

daemon 或持久 Job 状态不健康时，请查看[恢复指南](../help/recovery.md)。

## 远端到远端传输

两个 SSH 端点之间的复制使用两条普通 OpenSSH/SFTP 会话，并通过本地 daemon 的
受限内存中继。它不会：

- 把密钥、票据或 Agent 复制到服务器；
- 开启 Agent forwarding 或 GSS 凭据委托；
- 放宽主机密钥策略；
- 把完整传输文件保存到预览/编辑缓存。

公开构建不提供生产环境的服务器端加速或服务器间直传。标准 SFTP 始终是受支持的
通道。
